# Outline as written

Reverse-engineered from the finished draft, one sentence per paragraph. This is
not the plan, it is the map of what the post actually argues. `02-outline.md` is
kept as the historical record of what we intended; the comparison at the bottom
is the point of having both.

## Opening, no heading

1. I run many sessions in parallel, they spawn more, and past twenty or thirty
   of them the names are all I have left.
2. The names tell me nothing, and the failure lands the same afternoon rather
   than weeks later.
3. This is a naming problem, and naming is hard because the name must be chosen
   before anyone knows what the thing will become.
4. I named my daughters before they were born, for people nobody had met yet.
5. Other cultures wait and let the name be earned, which makes an early name an
   intention and a late one a description.
6. A session is named at birth too, by a machine, at the least informed moment
   in its life.
7. Writing better first messages does not help, because the context that would
   make the name right does not exist yet.
8. So I record where and when a session is instead of what it is, because both
   are true the instant it exists.
9. That flip is what made dozens of sessions manageable, since placing one no
   longer requires knowing what it is.
10. The work was always a tree, nothing displayed it as one, and the coordinates
    do.

## The knowledge graph built with pen and paper

11. The solution is Luhmann's Zettelkasten, and his output is the evidence it
    works.
12. His cards were numbered so the number said where a card sat rather than what
    was on it, and could be assigned the moment the card existed.
13. Nothing else recorded that 21a came from 21, so there was no index to
    maintain.

## One rule to organize them all

14. On my machine a session `21` spawns `21a`, which spawns `21a1`.
15. The grammar is one alternation rule, with no zero-padding, because the ID is
    for identity rather than sorting.
16. A title is the ID plus prose, and in practice I let the app write the prose.
17. The worktree directory carries the same ID, renamed exactly once, and only
    the ID has to match.
18. Branches never carry the ID, because reviewers see branches and the
    coordinate system is mine.
19. Numbers go in creation order and are never reused.
20. The convention is not specific to one tool.
21. The payoff is visual, because related IDs share their first characters.
22. All of it can be done by hand, and that costs nothing.

## Coding agents are vibe coded too

23. Automating it failed the same way in every tool, because a session is not a
    first-class object in any of them.
24. Claude Code knows a session is a fork and will not say what it forked from.
25. Four unrelated features implement one idea, a session that came from a
    session, and none share an identity space.
26. There is nowhere solid to stand, since a Codex subagent hook cannot stop the
    subagent.
27. So nothing local could answer what the next ID should be, and what worked
    was a single remote choke point.
28. That is a preposterous amount of machinery for a prefix, and it exists
    because the tools will not expose the relationship.
29. The code is public, it is not a product, fork it.

## One small ID, a whole lot of meaning

30. What surprises me is how small the cause is.
31. The sidebar is structurally identical and now related work sits together, so
    I find my place in a second.
32. I would rather not have built this, because a first-class session manager
    could simply show me the tree.
33. The work was always a tree. A knowledge tree.

## What the comparison shows

**Twelve nodes became five sections. Seventy-four planned items became
thirty-three paragraphs.** The plan was roughly twice the size of the post.

**Three whole nodes vanished, and all three were how-to.** The judgment calls
about filing, the minting rules, and the adoption pitfalls. Each was written
from design notes rather than from practice, and none survived contact with the
question "does the reader need this?"

**The strongest paragraphs were never in the outline.** Paragraph 25, the four
unrelated features. Paragraph 28, the preposterous machinery. Paragraph 32, not
wanting to have built it. All three arrived while writing the argument, and the
last is the emotional centre of the post's second half.

**The opening inverted.** The outline led with a data-structure mismatch, a
list where there should be a tree. The draft leads with naming and lands the
tree as the closing line of both the opening and the post. What was planned as
the frame became the payoff.

**Only one section survived roughly as planned.** "One rule to organize them
all" maps almost item for item onto outline node 6, because it is the only
section that describes mechanics rather than making an argument. Mechanics can
be outlined. Arguments apparently cannot.
